# Скрипты колонии для Screeps

Полноценный бот колонии для [Screeps](https://screeps.com) (официальный MMO-сервер, JavaScript). Сам развивает комнату от первого спавна до RCL 8: добывает, перевозит, строит, улучшает контроллер, чинит, защищается, планирует базу и расширяется в новые комнаты по флагам.

**Как играть с этими скриптами шаг за шагом — в [руководстве по игре](GUIDE.ru.md).**

## Установка

Игре нужны только `.js`-файлы из **корня репозитория**. Всё остальное (`test/`, `package.json`, `eslint.config.mjs`, `node_modules/`) — инструменты разработки, загружать их не нужно.

**Вариант А — встроенный редактор (браузер или Steam-клиент)**

1. Откройте вкладку *Script*, ветка `default` (или создайте новую ветку).
2. Для каждого `.js`-файла из корня создайте модуль с тем же именем **без** `.js` (`main`, `config`, `role.harvester`, `spawn.manager`, ...) и вставьте содержимое файла.
3. Удалите старый модуль `spawner`, если он остался, — он больше не используется.
4. Нажмите *Commit*. Бот заработает со следующего тика.

**Вариант Б — локальная папка (Steam-клиент)**

1. Во вкладке *Script* нажмите *Open local folder*. Клиент откроет папку текущей ветки, например
   `%LOCALAPPDATA%\Screeps\scripts\screeps.com\default` (Windows) или
   `~/Library/Application Support/Screeps/scripts/screeps.com/default` (macOS).
2. Скопируйте туда все `*.js` из корня репозитория (только файлы корня, без подпапок). Клиент загрузит их сам.
3. Удалите из этой папки старый `spawner.js`.

**Вариант В — загрузка через API.** Подойдёт любой загрузчик (например `grunt-screeps` или небольшой скрипт с `POST /api/user/code` и токеном): отправьте все `*.js` из корня как модули с именами без расширения.

Имена модулей плоские (`require('role.harvester')`), внешних зависимостей нет, код — ES2017, который поддерживает сервер Screeps.

## Архитектура

```
main.js               главный цикл: очистка → разведка → комнаты → крипы → терминалы → отчёт
config.js             все настройки и переключатели
utils.js              логи, обёртка try/catch, разбор имён комнат, CPU
cache.js              кэш room.find() в пределах тика
rooms.js              память комнат: привязки источников/контейнеров/линков, разведка
colony.js             флаги → директивы (claim / reserve / remote / attack / avoid)
body.js               построение тел по доступной энергии
population.js         чистый расчёт "кого не хватает" в комнате
spawn.manager.js      собирает состояние комнаты, спавнит по приоритету на всех спавнах
targets.js            резервирование целей, чтобы два крипа не шли к одной
movement.js           moveTo с кэшем путей, застреванием, обменом местами, безопасными маршрутами, бегством
creep.actions.js      общие действия крипов (взять/отвезти энергию, строить, чинить, апгрейд...)
combat.js             выбор целей для боевых ролей
threat.js             оценка опасности тел врагов, затухание урона башен
defense.js            оценка угрозы в своих комнатах, автоматический safe mode
structure.tower.js    башни: огонь / лечение / ремонт
structure.link.js     линки источников → линк контроллера / storage
structure.terminal.js балансировка энергии между своими терминалами
planner.layout.js     чистые функции планировки (шахматка, место спавна)
room.planner.js       расставляет строительные площадки по мере роста RCL
stats.js              статистика CPU и отчёт в консоль
console.commands.js   команды консоли (help(), stats(), ...)
roles.js              реестр ролей и их CPU-приоритеты
role.*.js             по файлу на роль
```

Каждый тик: удаляется память умерших крипов, обрабатываются флаги, сканируются видимые комнаты, в каждой своей комнате выполняются оборона → башни → линки → спавн → планировщик, затем работают крипы, сгруппированные по приоритету. Каждая комната и каждый крип выполняются в `try/catch`: ошибка в одном месте не останавливает колонию, сообщение выводится красным не чаще раза в 20 тиков на источник.

**CPU.** Результаты `room.find` кэшируются на тик, пути переиспользуются (`reusePath`), планировщик работает раз в ~100 тиков и хранит план в памяти. Если bucket ниже `cpu.lowBucket` (2000), приостанавливаются планировщик, терминал, разведчики и добыча минерала; ниже `cpu.criticalBucket` (500) работают только жизненно важные роли (харвестеры, майнеры, перевозчики, filler, защитники). При полном bucket (10000) генерируется пиксель (`toggles.pixels`).

## Роли и когда они появляются

Менеджер спавна раз в два тика пересчитывает нужный состав по состоянию комнаты и спавнит самого важного недостающего крипа. Тела масштабируются по `energyCapacityAvailable`; в аварийной ситуации (некому наполнять спавн) тело строится из энергии, которая есть прямо сейчас. Если комната 150 тиков не набирала полную энергию (например, расширение недоступно), тела строятся из того, что есть, вместо бесконечного ожидания.

| Роль | Что делает | Когда спавнится |
|---|---|---|
| `harvester` | Универсал ранней игры: добывает, наполняет спавн/расширения/башни, строит, улучшает. Когда у всех источников есть майнеры — работает перевозчиком. | Для источников без контейнера/линка: по 3 на источник при вместимости < 550, потом по 2 (не больше свободных клеток). Первый крип пустой колонии. |
| `miner` | Стационарный майнер на контейнере у источника; при линке рядом получает CARRY и сдаёт энергию в линк; чинит свой контейнер. | Один на каждый источник с контейнером (или линком + принимающим линком). Заменяется заранее, до смерти. |
| `hauler` | Возит энергию из контейнеров у источников, с земли, из надгробий и руин в спавн/расширения → башни → контейнер контроллера → storage. Вывозит минералы из контейнера у минерала. | Когда есть майнеры; число и размер — по расстоянию до источников (нужные CARRY / максимальный перевозчик, до 6). |
| `filler` | Менеджер базы от storage: наполняет спавн/расширения/башни, опустошает или наполняет линк у storage, держит энергию в терминале. | RCL ≥ 4, в storage ≥ 1000 энергии (или есть линк у storage). |
| `upgrader` | Улучшает контроллер, энергия — из линка/контейнера контроллера/storage. | `roles.upgraders[RCL]`; со storage: 1, пока < 20k энергии, +1 за каждые 50k сверх 100k; на RCL 8 — ровно 1 (лимит 15 WORK). |
| `builder` | Строит по приоритету: спавн → башня → контейнер → расширение → storage → линк → терминал → экстрактор → ... → дорога → рампарт → стена. Без строек — чинит, потом улучшает контроллер. | Когда есть площадки: 1 + 1 на каждые 15k оставшейся работы, до `roles.maxBuilders[RCL]`. |
| `repairer` | Чинит дороги, контейнеры и т.п. ниже 60%; на стены энергию не тратит. | ≥ 3 повреждённых построек и нет башен (или повреждений очень много). |
| `wallRepairer` | Поднимает рампарты и стены до `wallHits[RCL]`, начиная с самого слабого. | Есть стены/рампарты ниже цели, RCL ≥ 2, в storage ≥ 20k (если storage есть). 2 штуки при атаке игрока. |
| `defender` | Ближний бой. Дома держится на рампартах против игроков; в чужих комнатах зачищает врагов и ядра захватчиков. | При угрозе дома (башни не справляются / атака игрока), для опасных remote-комнат и для флагов `attack`. |
| `rangedDefender` | Стрелок: держит дистанцию 3 от бойцов ближнего боя, использует массовую атаку, когда это выгодно. | Вместе с защитниками (половина нужного числа). |
| `healer` | Лечит раненых своих крипов, следует за отрядом. | Атака игрока с лечением, отряды `attack`. |
| `claimer` | Захватывает контроллер комнаты с флагом `claim` (сначала атакует чужой резерв). | Флаг `claim`, у дома RCL ≥ 3 и вместимость ≥ 650. |
| `pioneer` | Идёт в захваченную комнату, добывает там, строит спавн, держит контроллер. На RCL 3 становится местным строителем. | По 2 на захваченную комнату, пока в ней нет спавна. |
| `reserver` | Держит резерв remote-комнаты (источники дают 3000 вместо 1500). | Комнаты `remote` / `reserve` с резервом < 3000 тиков, вместимость ≥ 650. |
| `remoteMiner` | Добывает удалённый источник, строит и чинит контейнер. Уходит, если в комнате опасно. | По одному на удалённый источник (RCL дома ≥ 3). |
| `remoteHauler` | Возит удалённую энергию домой, по пути чинит дороги. | На каждый удалённый источник, число/размер — по расстоянию. |
| `scout` | Одна MOVE-часть: посещает неизвестные целевые комнаты, затем исследует окрестности до 3 комнат от дома. | Когда о remote/claim/reserve комнате ещё нет данных. |
| `mineralMiner` | Добывает минерал комнаты (экстрактор) в контейнер рядом. | RCL ≥ 6, построены экстрактор и контейнер, минерал не истощён, в storage есть место. |

Порядок приоритетов: аварийное наполнение → майнеры/перевозчики/харвестеры → filler → оборона дома → первый апгрейдер → строители → ремонтники → укрепители стен → захват/пионеры → отряды атаки → удалённая добыча → дополнительные апгрейдеры → добытчик минерала → разведчик.

| `roles.pioneersPerClaim`, `roles.attackSquad` | Размеры экспансии и отряда атаки. |
| `wallHits` | Целевые хиты стен/рампартов по RCL. |
| `repair.*` | Порог ремонта (60%) и уровень "починено" (95%). |
| `storage.*` | Запас энергии для спавна; минимум storage для строителей и стен. |
| `tower.*` | Минимум энергии башни для ремонта, уровень ремонта рампартов, дорог/контейнеров. |

| `remotes` | `{ 'W1N1': ['W2N1', 'W1N2'] }` — remote-комнаты без флагов. |

| `planner.*` | Интервал планировщика, лимиты площадок на комнату/аккаунт, с какого RCL строить дороги/рампарты/контейнеры. |
| `movement.*` | `reusePath`, тики до пересчёта пути и обмена местами. |

## Флаги

Важно только **имя** (префикс без учёта регистра, цвет любой). Необязательный суффикс `@КОМНАТА` явно задаёт домашнюю комнату.

| Имя флага | Действие |
|---|---|
| `claim…` (например `claim1`, `claim@W5N8`) | Захватить комнату: claimer, затем 2 пионера строят спавн. Флаг снимается, когда в комнате появился свой спавн. |
| `spawn…` | Ставится в захваченной комнате: первый спавн будет построен ровно здесь. |
| `remote…` (например `remote1`, `remote2@W5N8`) | Удалённая добыча: разведчик → резервер + майнер + перевозчик на источник. Не больше `remote.maxRoomsPerHome` на дом. |
| `reserve…` | Только держать резерв контроллера. |
| `attack…` | Отправить отряд (`roles.attackSquad`) зачистить крипов и вражеские постройки. Снимается сам, когда комната 20 тиков чиста. |
| `avoid…` | Никогда не водить крипов через эту комнату. |
| `rally…` | Точка ожидания свободных крипов в этой комнате. |

Домашняя комната — ближайшая своя комната со спавном, подходящая по требованиям (claim: RCL ≥ 3 и вместимость 650; remote: RCL ≥ 3).

| Команда | Описание |
|---|---|
| `help()` | Список команд. |
| `stats()` | Отчёт по всем комнатам (RCL, энергия, storage, крипы по ролям, очередь спавна). |

## Разработка: тесты и линтер

Нужен Node.js 18+.

```bash
npm install
npx jest        # юнит-тесты + симуляция главного цикла на имитации Screeps
npx eslint .    # линтер (ES2017 для игровых файлов)
```

`@types/screeps` даёт автодополнение в редакторе (`jsconfig.json`). Тесты используют написанные вручную заглушки глобальных объектов игры (`test/mocks/`); симуляция гоняет настоящий `main.loop` тысячи тиков в фиктивной комнате. Игре всё это не нужно.

## Решение проблем

- **Красные строки `ERROR in ...`.** Сломанный крип/комната изолированы, остальное работает. В сообщении есть стек вызовов — по нему видно место ошибки.
- **Ничего не спавнится.** `roomInfo('W1N1')` покажет очередь. Большие тела ждут полной энергии; через 150 тиков без полной энергии колония спавнит из того, что есть. Claimer требует вместимости 650.
- **Крипы застревают.** После 2 тиков без движения путь пересчитывается, после 3 — обмен местами с мешающим своим крипом. Проверьте флаги `avoid`; `resetRoom()` перестроит план.
- **Площадки в неудобном месте.** `clearSites('W1N1')` и `resetRoom('W1N1')`. Для новой комнаты поставьте флаг `spawn` до захвата.
- **Старые крипы прошлого скрипта** (harvester/builder/upgrader) продолжают работать; неизвестные роли отправляются на переработку.

Больше сценариев — в [руководстве по игре](GUIDE.ru.md#частые-вопросы-и-проблемы).
